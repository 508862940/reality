## 🧩 多层次架构设计

### ✅ 正确理解（交响乐团比喻）

```
🎭 游戏事件（User做了某事）
   ↓
┌─────────────────────────────────────┐
│  🎻 演奏家层（Musician Layer）       │
│  ================================   │
│  1. EmotionSystem                  │
│     - 输出：{affection, trust, ...}│
│                                     │
│  2. MemorySystem                   │
│     - 输出：{todayGreeted, ...}    │
│                                     │
│  3. NPC基础状态                     │
│     - 输出：{health, mood, ...}    │
└─────────────────────────────────────┘
   ↓
┌─────────────────────────────────────┐
│  🎼 加工层（Processing Layer）      │
│  StateVectorBuilder.build()        │
│  收集所有演奏家的声音，加工成：      │
│  [0.5, 0.1, 0.7, 0.3, ...]         │
└─────────────────────────────────────┘
   ↓
┌─────────────────────────────────────┐
│  🎺 指挥家层（Conductor Layer）     │
│  UtilityAI.decide()                │
│  矩阵 × 向量 = 行为分数              │
│  选择最高分的行为                    │
└─────────────────────────────────────┘
   ↓
🎵 Zero做出最终行为
```

## ⚠️ 常见误解澄清

### 误解1：状态向量都是Zero的

❌ **错误**：[0-2] 是Zero的血量、创伤、心情

✅ **正确**：
- [0-2] 是 **User** 的状态
- [5-9] 是 **Zero** 的状态
- [10-13] 是 **Zero对User** 的情感

**为什么这样设计？**
- Zero需要**感知User的状态**才能做决策
- 例如：User受伤了 → Zero想保护 → 权重设计为负值（User血量越低，"保护User"分数越高）

---

### 误解2：情感就是状态的一部分

❌ **错误**：情感和状态是一回事

✅ **正确**：它们是**不同层次**的数据：

```
基础状态（原料）:
  - Zero的血量、心情、狼魂控制
  - User的血量、创伤、心情

情感系统（加工后的数据）:
  - 好感度、信赖度、尊敬度、迷恋度
  - 有增长速率、关系阶段判定

记忆系统（历史数据）:
  - 今天的事件记录
  - 影响未来决策的权重

状态向量（最终混合物）:
  - 把所有"演奏家"的声音汇总
  - 统一成22维数组
  - 供Utility AI使用
```

**层次关系**：
```
原料层: health, mood, trauma ...
     ↓
加工层: EmotionSystem.playNotes() → {affection: 0.7, ...}
       MemorySystem.playNotes() → {todayGreeted: 1, ...}
     ↓
混合层: StateVectorBuilder.build() → [0.5, 0.1, 0.7, ...]
     ↓
决策层: UtilityAI.decide() → "保护User"
```

## 🎯 权重设计原则

### 原则1：明确区分"谁的状态"

**示例：User创伤高时的权重设计**

```javascript
"热情打招呼": [
    ...
    -0.6,  // [1] User创伤
    ...
]
```

**解读**：
- User创伤 = 1.0（满创伤）
- 权重 = -0.6
- 贡献分数 = 1.0 × (-0.6) = -0.6
- **结果**：User受伤严重时，"热情打招呼"分数大降，Zero会选择"保护User"

---

### 原则2：Zero自身状态也要考虑

**示例：Zero心情对社交的影响**

```javascript
"热情打招呼": [
    ...
    0.5,   // [6] Zero心情（心情好才能热情社交！）
    ...
]
```

**解读**：
- Zero心情 = 0.2（心情很差）
- 权重 = 0.5
- 贡献分数 = 0.2 × 0.5 = 0.1（很低）
- **结果**：Zero心情差时，即使好感度高，也不想热情打招呼

---

### 原则3：情感影响行为选择，但不是唯一因素

**示例：高好感度但User受伤**

```javascript
状态向量 = [
    0.1,   // [0] User血量（血量低）
    1.0,   // [1] User创伤（满创伤）
    0.3,   // [2] User心情（心情差）
    ...
    0.8,   // [10] 好感度（很高！）
    ...
]

"热情打招呼"分数:
  = 0.1×0.1 + 1.0×(-0.6) + 0.3×0.4 + ... + 0.8×0.8 + ...
  = 0.01 - 0.6 + 0.12 + ... + 0.64 + ...
  ≈ 0.17（低）

"保护User"分数:
  = 0.1×(-0.3) + 1.0×(-0.5) + 0.3×(-0.4) + ... + 0.8×0.7 + ...
  = -0.03 - 0.5 - 0.12 + ... + 0.56 + ...
  ≈ 0.45（高！）

结果：选择"保护User"而不是"热情打招呼"
```

**涌现行为**：即使好感度很高，Zero也会先关心User的伤势，而不是傻傻地热情打招呼！

## 📐 权重调整技巧

### 技巧1：负权重 = 反向影响

```javascript
-0.6  // User创伤越高，分数越低
0.6   // 好感度越高，分数越高
```

### 技巧2：权重大小 = 重要性

```javascript
0.8   // 非常重要（好感度对打招呼的影响）
0.3   // 中等重要（尊敬度）
0.0   // 不关心（药物对打招呼无影响）
```

### 技巧3：阈值效应

```javascript
// 想要"好感度必须>60才会热情打招呼"
// ❌ 错误：if (affection > 0.6) score += 50;
// ✅ 正确：用权重组合实现
"热情打招呼": [
    ...
    0.8,   // [10] 好感度（主要得分）
    0.5,   // [11] 信赖度（辅助得分）
    ...
    -0.4,  // [14] 今日已问候（避免重复）
]

// 当好感度<60时，其他负权重会拉低总分
// 当好感度>60时，正权重占主导，总分升高
```

const stateVector = StateVectorBuilder.build(zero, context);

### 2. 手动计算分数

```javascript
const weights = zero.utilityAI.decisionMatrix["保护User"];
let score = 0;
for (let i = 0; i < stateVector.length; i++) {
    const contribution = stateVector[i] * weights[i];
    console.log(`[${i}] ${stateVector[i].toFixed(2)} × ${weights[i]} = ${contribution.toFixed(3)}`);
    score += contribution;
}
console.log('总分:', score);
```

## ⚠️ 重要提醒

1. **状态向量维度固定**：所有权重数组必须是22维，否则点积计算会出错
2. **归一化很重要**：所有状态值应该在0-1范围内，权重在-1到1之间
3. **测试很重要**：每次修改权重后，用多个场景测试，确保行为合理
4. **记忆要重置**：测试时记得在每次决策前重置记忆，避免累积

## 📖 总结

这是一个**真正的Utility AI系统**：

- **不是**简单的加减法游戏
- **不是**好感度攻略
- **是**基于矩阵×向量的决策引擎
- **是**多维度、多因素综合评估的涌现式AI

**核心公式**：
```
行为分数 = Σ(状态[i] × 权重[i])
最终行为 = argmax(所有行为分数)
```

这就是博德之门3、辐射4、刺客信条等AAA游戏使用的AI技术！🎮
